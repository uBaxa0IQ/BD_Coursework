# Данные NBA Stats

`csv_2021-2026/` — сохранённый срез базы за сезоны 2021–22 — 2025–26: 30 команд, 5 126 записей игроков, 6 140 матчей, 159 652 выступления и 2 897 сезонных агрегатов. Наличие сезона в срезе не означает полноту всех данных этого сезона.

Восемь CSV соответствуют базовым таблицам. Файлы `v_*.csv` — выгрузки четырёх представлений для самостоятельного анализа; импорт их пропускает, поскольку PostgreSQL вычисляет представления по базовым таблицам. Идентификаторы сохраняются, последовательности восстанавливаются.

## Импорт среза

Из каталога `code`, после запуска Docker Compose:

```bash
docker compose exec -T -e DATABASE_URL=postgresql://nba_admin:nba_secure_pass_2024@postgres:5432/nba_stats backend python scripts/import_db.py --in csv_2021-2026
```

Операция заменяет содержимое базовых таблиц в одной транзакции. Сезонные агрегаты берутся из CSV, а не пересчитываются при каждой вставке. Перед импортом собственных данных сделайте экспорт.

## Экспорт

```bash
docker compose exec -T -e DATABASE_URL=postgresql://nba_admin:nba_secure_pass_2024@postgres:5432/nba_stats backend python scripts/export_db.py
```

Результат появится в `code/data/csv_export/` на хосте. Каталог исключён из Git. Параметр `--out my_backup` выбирает другую подпапку `data/`; абсолютный путь поддерживается для импорта и экспорта.

## Другие источники

Свежие данные загружает `backend/scripts/load_data.py` через `nba_api`. Это отдельный долгий процесс, зависящий от доступности NBA Stats и ограничений внешнего API. Параметры доступны через `python scripts/load_data.py --help` внутри backend-контейнера.

Для воспроизводимых демонстраций без обращения к внешнему API есть `backend/scripts/load_synthetic_data.py`. Его данные искусственные; команда с `--reset` очищает существующие игровые данные.

Загрузчикам, как и импорту, нужен URL владельца БД в переменной `DATABASE_URL`, поскольку они отключают триггеры на время пакетной записи. Не запускайте их на БД с нужными вам данными без резервной копии.

Источник реальной статистики — NBA Stats через `nba_api`. История контрактов реконструируется эвристически по выступлениям, поэтому не является официальной историей сделок. Права на исходные данные остаются у их владельцев.
