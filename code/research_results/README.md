# Исследование производительности

`run_10k/` содержит сохранённый прогон, использованный в пояснительной записке. Это исторические измерения; очистка репозитория их не перезапускала.

Стенд: Intel Core i5-1235U, 16 ГБ DDR4, NVMe SSD; PostgreSQL 15, Redis 7 и API на одном хосте в Docker. В таблице `game_player_stats` — 159 652 строки за пять сезонов.

Для SQL выполнялись 10 прогревочных и 10 000 рабочих запросов. Cache Miss измерялся на 30 запросах со сбросом кэша, Cache Hit — на 10 000 запросах после прогрева. Нагрузка — 1, 10, 50 и 100 параллельных запросов, по 10 раундов. JSON сохраняет медиану, среднее, p95 и долю ошибок.

## Что сравнивается

- Прямая агрегация фактов и предвычисленная сезонная витрина при добавлении сезонов.
- Влияние индексов на тяжёлый запрос.
- HTTP API при промахе и попадании в Redis.
- Время ответа API при разном числе параллельных запросов.

Прямая агрегация сортирует по сумме очков, запрос к витрине — по PER. Это сравнение сценариев сезонной аналитики; оно не доказывает ускорение одного и того же SQL-запроса с идентичным результатом. Значения зависят от стенда, данных, прогрева и нагрузки. Исходная методика приведена в `report/research_part.tex`.

## Повторный запуск

Скрипт: `backend/scripts/research/performance_study.py`. Запускайте его на отдельной тестовой базе: исследование создаёт и удаляет индексы, меняет настройки сессии и сбрасывает кэш.

Из каталога `code`, при работающем Compose и загруженных данных:

```bash
docker compose exec -T -e DATABASE_URL=postgresql://nba_admin:nba_secure_pass_2024@postgres:5432/nba_stats -e API_BASE_URL=http://backend:8000 -e SECRET_KEY=your-secret-key-here -e ITERATIONS=10000 -e RESEARCH_RESULTS_DIR=/app/research_results backend python scripts/research/performance_study.py
```

`SECRET_KEY` должен совпадать со значением в вашем `code/.env`. Новые результаты появятся в локальном `code/backend/research_results/`, исключённом из Git. Сохранённый `run_10k/` при этом останется прежним. Параметр `ITERATIONS` управляет рабочими повторами SQL и Cache Hit; раунды параллельной нагрузки заданы в скрипте.
